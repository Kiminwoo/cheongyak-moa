# 청약모아 · React 반응형 웹앱 0.2

코드 저장소: [Kiminwoo/cheongyak-moa](https://github.com/Kiminwoo/cheongyak-moa)

개발·브랜치·CI 안내는 [CONTRIBUTING.md](CONTRIBUTING.md)를 확인하세요.

사용자가 희망 조건을 입력하고 여러 기관의 청약을 비교하는 로컬 개발 서비스입니다. 프런트엔드를 React로 전환했습니다. 기존 Node.js 서버·SQLite DB·API 경로는 유지하며, 클라우드 없이 현재 PC에서 실행합니다. 최초 실행에는 React·빌드 도구 설치를 위한 인터넷 연결이 필요합니다.

## 실행

Node.js 22.15 이상이 필요합니다. Windows에서는 `start.cmd`를 실행하세요. 패키지가 없으면 설치한 뒤 React 화면을 빌드하고 서버를 실행합니다. 프로젝트 폴더에서 직접 실행하려면 다음 순서로 진행합니다.

```powershell
npm.cmd install
npm.cmd start
```

브라우저: <http://127.0.0.1:4310>

`npm start`는 `prestart`에서 화면을 자동 빌드합니다. 최초 설치 이후에는 소스 수정 시에도 `npm start`만 실행하면 됩니다. 종료는 실행 창에서 Ctrl+C입니다. 포트 변경은 `.env`의 `PORT`로 설정합니다. 서버는 127.0.0.1에만 바인딩합니다. 인터넷 공개 운영용 구성이 아닙니다. 빌드 전에는 기존 DOM 조작 스크립트를 제공하지 않으며 설정 안내 화면을 표시합니다.

현재 코딩 실행 환경은 npm 레지스트리 네트워크 접근이 제한되어 있어 의존성 다운로드·React 번들 빌드·React DOM 테스트를 완료하지 못했습니다. 아래 일반 테스트는 외부 패키지 없이 실행할 수 있습니다. 네트워크가 가능한 PC 터미널에서 설치 후 `npm run build`와 `npm run test:ui`를 실행해 검증을 마쳐야 합니다. 첫 설치 시 생성되는 `package-lock.json`은 함께 보관하세요.

## 프런트엔드 구성

- React 19: `createRoot`, 함수형 컴포넌트, Hooks, React 이벤트 처리
- esbuild: JSX 변환 및 로컬 JavaScript 번들 생성. 브라우저 CDN 의존 없음
- 모바일: 하단 메뉴, 접을 수 있는 필터, 1열 카드, 날짜별 일정 목록
- 태블릿: 조건 영역과 결과 영역 재배치, 2열 카드
- PC: 조건 사이드바와 공고 목록. 큰 화면은 3열 카드
- 작은 화면의 입력 요소는 16px 글자, 터치 요소는 주로 44px 이상, safe-area 반영
- PWA: manifest, 192/512 PNG 및 maskable 아이콘, 홈 화면/독립 창 설치 안내, Service Worker

설치 지원 여부는 브라우저에 따라 다릅니다. HTTPS 또는 localhost에서 동작합니다. PC 로컬 주소를 휴대폰에서 직접 사용할 수는 없습니다. 휴대폰 사용에는 별도 네트워크·배포 설정이 필요합니다.

참고: [React 기존 프로젝트 적용 안내](https://react.dev/learn/add-react-to-an-existing-project), [MDN PWA 설치 조건](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

Service Worker는 앱 화면 파일만 캐시합니다. `/api/` 응답과 사용자 조건·공고 정보는 캐시하지 않습니다. 이미 열린 화면은 메모리에 남을 수 있으나, 서버가 꺼진 상태에서는 저장·수집·최신 조회가 불가능합니다. 앱 설치가 서버의 상시 실행을 대신하지 않습니다.

Node 22의 내장 SQLite는 실험 기능 경고를 출력할 수 있습니다. 실행 스크립트에 필요한 플래그가 포함되어 있습니다.

## 구현된 기능

- 사용자 관심 지역·주거유형·분양 예산·임대 보증금·월세 입력과 로컬 DB 저장
- 선택 입력: 생년월일·본인 주택 보유 여부
- 공고 검색, 지역·유형·데이터 구분·마감 여부 필터, 추천·마감·최신순 정렬
- 입력 조건에 따른 추천 이유와 정보 부족 상태 표시
- 가상 청년주택 공고의 예시 규칙 비교: 공고 기준일 연령과 본인 보유 여부
- 관심 공고 저장·해제, 접수 시작·마감 달력, ICS 파일 다운로드
- 출처별 연동 상태·수집 이력·공고 변경 버전 조회
- 청약홈 3개 목록 유형 및 LH 주거용 공고 목록 수집 어댑터
- 원본 JSON 보관, 필수 식별자 검증, 중복 방지, 변경 버전 보존, 실패 기록
- 입력 조건·관심 공고 삭제

## 데이터의 의미

최초 실행 시 9개의 **가상 공고**를 생성합니다. 공고명·금액·물량·일정·자격 조건은 실제 정보가 아닙니다. 예시 일정은 최초 DB 생성 당시 한국 날짜 기준이며 실행할 때마다 이동하지 않습니다. 예시 공고에는 신청 링크가 없습니다.

‘예시 조건 일치’는 테스트 규칙이 일치한다는 의미입니다. 실제 공고 자격을 보장하지 않습니다. 공식 API 공고는 실제 자격 규칙이 검토되기 전까지 **공고 확인 필요**로 남습니다. 본인 주택 보유 여부만으로 세대 무주택 여부를 판정하지 않습니다.

지역·예산은 선호로 처리합니다. 조건 밖 공고와 가격 미확인 공고를 자동 삭제하지 않습니다. 실제 신청 자격·우선순위와 선호 점수는 다릅니다.

기본 화면은 예시 자료만 표시합니다. 공식 수집 후 좌측 ‘데이터 구분’을 ‘공식 API 수집 공고’로 바꾸세요.

## 공식 데이터 연결

1. 아래 공식 API 페이지에서 본인 계정으로 활용 신청합니다.
2. `.env.example`을 `.env`로 복사합니다.
3. 발급받은 일반 인증키(Decoding)를 해당 항목에 입력합니다. 키를 채팅·화면·공개 저장소에 게시하지 마세요.
4. 서버를 다시 실행합니다.
5. ‘데이터 연결 현황’ → ‘공식 공고 수집 실행’을 누르거나 `npm.cmd run collect`를 실행합니다.

```dotenv
APPLYHOME_SERVICE_KEY=본인의_청약홈_인증키
LH_SERVICE_KEY=본인의_LH_인증키
PORT=4310
COLLECT_LOOKBACK_DAYS=180
```

키가 하나만 있어도 해당 출처만 수집합니다. 기본 수집 범위는 최근 180일 모집공고입니다. 전체 과거 공고·전국 모든 기관을 수집하지 않습니다. 주기 자동 실행은 아직 없으며 버튼이나 CLI로 실행합니다. 서버 수집과 CLI를 동시에 실행하지 마세요.

공식 자료:

- [한국부동산원 청약홈 분양정보 API](https://www.data.go.kr/data/15098547/openapi.do)
- [한국부동산원 기술문서](https://www.reb.or.kr/reb/na/ntt/selectNttInfo.do?mi=10251&bbsId=1268&nttSn=79889)
- [LH 분양임대공고문 API](https://www.data.go.kr/data/15058530/openapi.do)

현재 어댑터는 인증키 없는 환경에서 모의 응답으로 검증했습니다. 실제 승인키를 이용한 라이브 통신·최신 응답 명세 대조는 후속 확인이 필요합니다. 최초 실행에서는 원문과 표본 대조 후 사용하세요.

청약홈: APT, 무순위·잔여세대, 오피스텔·도시형·민간임대의 목록 요청을 구현했습니다. 주택형별 금액·공급유형별 상세 일정은 후속 수집 대상이며 목록에 없는 가격을 추정하지 않습니다.

LH: 분양주택·임대주택·주거복지·신혼희망타운 공고유형의 목록 요청을 구현했습니다. 공고게시 종료일은 청약 접수 마감일과 구분하므로 접수일로 사용하지 않습니다. 상세 일정은 원문 확인이 필요합니다.

SH·GH·기타 지방공사·지자체는 연동 대상 목록만 등록했습니다. 공식 수집 공고에 포함되지 않습니다. 제공 범위·이용조건을 확인한 후 별도 어댑터를 추가해야 합니다.

## 저장 구조와 개인정보

```text
data/
  cheongyak.sqlite        공고·버전·사용자 조건·관심 공고·수집 이력
  raw/{기관}/{실행번호}/   공식 API 원본 JSON
src/
  store.js               SQLite 저장 계층
  matching.js            입력 검증·추천 이유·예시 규칙
  collectors.js          공식 목록 API 어댑터
  demo.js                가상 공고
frontend/
  App.jsx                앱 상태·API 연결·페이지 전환
  components.jsx         메뉴·조건·공고·달력·모달 등 React 컴포넌트
  lib.js                 필터·금액·날짜·ICS 유틸리티
  main.jsx               React 진입점·Service Worker 등록
public/
  index.html             React 루트 HTML
  app.js                 빌드 결과 (직접 수정하지 않음)
  style.css              기본 디자인
  responsive.css         반응형·터치·safe-area 레이아웃
  manifest.webmanifest   PWA 설치 정보
  sw.js                  화면 파일 전용 캐시 정책
  icons/                 앱 설치 아이콘
scripts/build.mjs        React 번들 빌드
test/                    기능·저장·API·보안 회귀 테스트
```

이 버전은 한 명이 사용하는 로컬 개발 도구입니다. 입력한 사용자 조건은 SQLite에 저장되며 별도 DB 암호화는 하지 않습니다. 주민등록번호·인증서·실제 증빙서류 입력은 받지 않습니다. 공용 PC에서 사용하지 말고 조건 설정 창의 ‘내 정보·관심 공고 삭제’를 이용하세요. DB의 외부 백업 사본은 따로 관리해야 합니다.

API 키는 환경변수로만 읽으며 브라우저에 반환하지 않습니다. `.env`와 `data/`는 Git 제외 대상입니다. 원본 응답에는 키가 포함된 요청 URL을 기록하지 않습니다.

## 검증

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:ui
```

`npm test`: 한국 날짜, 날짜 오류, 예산 구분·미확인, 나이 기준일, 규칙 미검토·정보 부족 처리, 저장·재실행·삭제, 중복 수집·정정 버전, API 응답 오류, 인증키 비노출, 로컬 요청·교차 출처 차단, 입력 크기 제한, 프런트 필터·달력·ICS, manifest·아이콘 응답, Service Worker 캐시 경계. 현재 40개 통과.

`npm run test:ui`: happy-dom에서 React 컴포넌트 렌더링·조건 저장·관심 저장·모달·탭 이동·오프라인 상태를 검증합니다. 설치 후 실행해야 하며 현재 환경에서는 미실행입니다. DOM 테스트는 실제 브라우저의 화면 크기별 시각 검증이나 앱 설치 검증을 대체하지 않습니다.
